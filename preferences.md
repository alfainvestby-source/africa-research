# Preferences

- [No AI-invented property facts](preferences.md) — every field needs a cited source or explicit `unknown`; never fill gaps with model guesses. (2026-10-15)
- [Developer sources outweigh agents](preferences.md) — weight official developer / project-site data above agent and aggregator listings when compiling master records. (2026-10-15)
- [Learning loop before scale](preferences.md) — pilot 1–2 → review → next 2 → retrofit → then half remainder; must-have fields emerge from analysis. (2026-10-15)
- [Confidence is internal](preferences.md) — store confidence on claims for the model/QA; do not show confidence in the public portal initially. (2026-10-15)
- [Relational entity model](preferences.md) — Property, Developer, optional GroupCompany, Agent, Contact, Stakeholder, Source, Claim; agents and contacts linked to properties. (2026-10-15)
- [Unproven brand overlap = marketing_partner](preferences.md) — do not treat as GroupCompany/parent until proven (e.g. Laureland↔Wimax). (2026-10-15)
- [Developer wins canonical on conflict](preferences.md) — highlight all conflicts; if developer known with developer sources for a field, canonical value is developer. (2026-10-15)
- [Payment plan ≥4 agent sources](preferences.md) — payment plan is must-have when ≥4 independent agent/portal sources agree, or any developer source. (2026-10-15)
- [Living must-have list with consensus](preferences.md) — extend must-haves as evidence appears; track consensus per item. (2026-10-15)
- [Sources: scan ~10, keep ≥5 densest](preferences.md) — evaluate about 10 candidates; retain at least 5 info-rich sources; always keep developer/official site; skip thin pages early. (2026-10-15)
- [Show low-confidence claims with needs_verification](preferences.md) — display agent-only/sold-out/uncorroborated claims; mark needs_verification when low confidence; do not hide. (2026-10-15)
- [Standing proptech DB steward](preferences.md) — keep a relational DB model (schema, seed, notes, changelog) continuously updated from research; classifieds/proptech best practices. (2026-10-16)
- [Document decisions in markdown as we go](preferences.md) — every lock goes into docs/decisions.md (and linked goal/context/schema/db docs) the same day. (2026-10-16)
- [Rightmove-class product north star](preferences.md) — target public + Admin + Plus quality; strong data layer; professional well-calculated data decisions. (2026-10-16)
- [Proactively propose new agents](preferences.md) — as gaps appear, propose specialist agents with **new skills** (not only more research clones); document in agent-roster.md. (2026-10-16)
- [Do not use majengo.co.ke](preferences.md) — no research, fetches, or integrations from majengo.co.ke / app.majengo.co.ke. (2026-10-16)
- [Majengo2 = Cursor Project](preferences.md) — “Majengo2” refers to the user’s Cursor Project of that name; use that app/codebase for filter intel, not the public majengo.co.ke site. (2026-10-16)
- [Kenya-wide discovery](preferences.md) — find off-plan/new developments across all Kenya; Nairobi is the first deep-research corpus. (2026-10-16)
- [Developments only, not unit listings](preferences.md) — entity of record is new developments/projects; skip standalone apartment/house listings; unit-type facts only when multi-source and reliable. (2026-10-16)
- [Block.ke is low-trust](preferences.md) — treat block.ke as a lead/forensics index only; never conf ≥3 or dossier authority without a non-Block primary source. (2026-10-16)
- [Hauzisha phone ≠ developer](preferences.md) — `0730 731 355` is Hauzisha’s number only; never assign it as a developer sales contact. (2026-10-16)
- [Skip Ready — only Off-plan / Building](preferences.md) — portal tags: skip anything tagged Ready (units or whole projects); research only Off-plan and Building / under construction. Ready rows are stored with `inventory_class=ready` but not dossiered for now (optional later). (2026-10-16)
- [inventory_class on listings](preferences.md) — mark Ready unit ads and Ready/handed-over developments; classes: off_plan | building | ready | resale. Coming-soon hubs stay in the review process. (2026-10-16)
- [Product v1 = off-plan/new-dev; Ready/resale later](preferences.md) — ship developments/off-plan first; keep schema so Ready and resale listings can be added easily without redesign. (2026-10-17)
- [Public grain = 2B development-first](preferences.md) — public is development pages; typology-linked listing snapshots from retained URLs only; no invented unit IDs. Evidence: docs/product/zillow-rightmove-model-study.md. (2026-10-17)
- [Agent phones on Plus only](preferences.md) — public shows developer/project CTA; full agent/WhatsApp graph is Plus. (2026-10-17)
- [Ready UI = 8B](preferences.md) — Plus/Admin may show Ready unit cards (not research-verified badge); public stays off-plan/UC; no auto-dossiers for Ready. (2026-10-17)
- [Kenya utilities vocab not EPC](preferences.md) — generator/borehole/solar/fibre/security; no UK EPC chase; named green certs only if developer publishes. (2026-10-17)
- [Bathrooms two grains](preferences.md) — `unit_type.bathrooms` per typology when sourced; development min–max derived for filters/cards; never invent. (2026-10-18)

- [Public fields = ~70% + high trust](preferences.md) — promote fields filled on ~70%+ of projects and backed by developer or ≥2 real agents, not single-agent AI filler. (2026-10-18)
- [CSV now, Postgres at UI](preferences.md) — keep improving seed CSVs until portal UI ships, then stand up Postgres. (2026-10-18)
- [Map location mandatory](preferences.md) — every project needs a map: online first (developer/EIA → Google/OSM); exact pin when strong, Approximate/Area-only badge when weaker; physical visit only if online fails. (2026-10-18)
- [Do not strip image watermarks](preferences.md) — never remove Hauzisha/portal watermarks; prefer developer/official photos for public galleries; watermarked portal shots Admin/Plus evidence only or exclude. (2026-10-18)
